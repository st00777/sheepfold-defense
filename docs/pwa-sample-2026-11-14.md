# PWA 樣品：加到主畫面＋沒網路也能玩（2026-11-14）

藍圖 [endgame-blueprint-2026-10-28.md](endgame-blueprint-2026-10-28.md) §4 樣品輪的第一個。James 11/14 同意先做這個。
**這是樣品，做在分支 `feat/pwa-sample`，沒有合進正式站。** 過了真機驗收、James 說要，才合。

## 1. 玩家會得到什麼

- 手機瀏覽器選「加入主畫面」，桌面多一個羊圈守夜的圖示。點開沒有網址列，像一般 App。
- 開過一次之後，沒網路（飛航、地下室、訊號差）也開得起來、玩得下去。
- 平常有網路時跟現在一樣，上了新版照樣拿到新版。

## 2. 做法（白話）

多了一支小程式 `sw.js`，住在玩家的瀏覽器裡，幫遊戲把檔案存一份在手機上。它只有三條規則：

1. **開頁永遠先問網路。** 拿到的就是最新的首頁。沒網路，或 3 秒沒回，才用上次存的那份。
2. **其他檔（程式、圖）先給存的那份，同時在背景跟伺服器對一次。** 有新的就換掉，下一次開就是新的。
3. **帶版本號的檔（`data.js?v=29` 這種）換了號就是新檔，直接抓新的，順手把舊號丟掉。**

最怕的事是「存了舊檔，上了新版玩家卻一直拿舊的」。所以這支程式裡**沒有任何版本號清單**。要先存哪些檔，是安裝當下去讀首頁抓出來的。

**上版流程完全不變**：照舊改 `index.html` 裡的 `?v=` 就好，不用碰 `sw.js`。就算哪天忘了加 `?v=`，規則 2 也會讓玩家在下一次開的時候拿到新檔（現在沒有這支程式時，忘了加會卡在舊檔比較久）。

## 3. 改了哪些檔

| 檔案 | 內容 |
|---|---|
| `sw.js`（新） | 上面三條規則，約 150 行，每段有白話註解 |
| `manifest.json`（新） | 告訴手機：名字、圖示、全螢幕開、底色 |
| `img/icon-192.png`（新） | 從 512 的圖示縮出來的小圖示 |
| `index.html` | 開頭加 5 行（掛上面那張說明＋iPhone 主畫面設定）；結尾加一小段把 `sw.js` 裝起來 |
| `sim/pwa-2026-11-14.test.js`（新） | 10 條測試，把 `sw.js` 放進假的瀏覽器真的跑 |

沒動任何既有的 js，所以這次沒有 `?v=` 要加。樣品不發更新公告，遊戲內版本與更新紀錄沒動。

本機開發（localhost）預設**不裝**這支程式，免得改檔時被存的舊檔騙到；網址帶 `?sw` 才裝，沒帶就把之前裝的拆掉。

## 4. 對照藍圖的通過標準

藍圖寫的標準：「更新後無痕與舊快取都拿到新版」，而且不能跟 `?v=` 版號打架。

**測試（假瀏覽器，213 項全綠，其中 10 條是這次新的）**

- 安裝時讀首頁、把它用到的檔連版本號一起存；別的網域（GA 統計）不碰；`sw.js` 裡沒有寫死任何 `?v=`。
- 開頁先問網路；帶 `?all&dev` 也一樣；斷線用存的；伺服器回錯誤用存的；第一次來又斷線就照實失敗。
- 網路卡住不回，超過時限用存的。
- `?v=` 換號：當次就拿新檔，舊號從存的裡面丟掉。
- 沒版本號的檔：這次開給存的，下次開就是新的；同一次開不重複抓。
- 背景更新一定跟伺服器對過；每開一次頁重新對一輪。
- 被轉址到別的網域的圖（測試站才有）：第一次照給，背景另外存一份，下次與斷線都有。
- 不該管的不管（別的網域、送資料的請求、`sw.js` 自己、proto 底下的頁面）。
- 說明檔欄位、圖示檔存在且尺寸對、首頁有掛。

**真瀏覽器（電腦 Chrome，本機伺服器）**

| 項目 | 結果 |
|---|---|
| 裝得起來、接手頁面 | 過 |
| 存了什麼 | 過。第一次 56 個檔，重新整理後補到 104 個；別的網域 0 個 |
| 說明檔讀得到（名字、全螢幕、圖示 3 個） | 過 |
| 關掉伺服器後重新整理 | 過。首頁正常，8 支程式都載入 |
| 離線進一夜 | 過。棋盤、格子、牧人、上排四張單位卡都是正常的圖，不是符號備援。**敵人沒驗到**（那一夜還在教學，沒開打） |
| 離線時 console | 沒有錯誤 |
| `?v=` 換號（data.js 29 改 30） | 過。重新整理一次就是新版，存的裡面只剩新號 |
| 沒版本號的檔（pixi）改了 | 過。第 1 次重新整理還是舊的，第 2 次是新的 |
| 同一個檔再改一次，什麼都不重啟 | 過。一樣第 2 次拿到 |
| 本機不帶 `?sw` 開 | 過。之前裝的被拆掉 |

**驗的過程抓到一個錯，已修**：第一輪「沒版本號的檔」不過，重新整理三次都是舊的。原因是背景更新那一趟沒有要求跟伺服器對，被瀏覽器自己留的舊檔攔下；而且每個檔在這支程式活著的期間只對一次。修法：背景更新一律跟伺服器對過（沒變只回一行，不會整個重抓），每開一次頁重新對一輪。補了一條測試釘住。修完重驗才是上表的結果。

**真瀏覽器（電腦 Chrome，githack 測試站）**

測試站關不掉網路，所以這裡驗的是「頁面用到的每個檔，存的那份拿不拿得出來」。

| 項目 | 結果 |
|---|---|
| 裝得起來、接手頁面 | 過 |
| 說明檔 `manifest.json` 讀得到 | 過 |
| 進一夜後，頁面用到的 56 個檔 | 56 個都存了，每個都拿得出來、內容不是空的 |
| 轉址的圖（測試站特有） | 過。存得下來 |
| 重新整理再進同一夜 | 過。一樣 0 個缺 |
| 敵人的圖 | 過。第 1 波的狼正常畫出、有血條 |
| console | 沒有錯誤、沒有警告 |

**測試站又抓到兩個錯，已修**：
1. 說明檔原本叫 `manifest.webmanifest`，測試站會把它轉到別的網域，起始網址失效。改名 `manifest.json`。
2. 進局後才載的圖（看門的那張）一直存不進去。原因是測試站的圖是轉址來的，一般的圖片請求拿到「看不到內容」的回應。改成背景另外抓一份存，補了一條測試。這條只有測試站會碰到。

**還沒驗的**：真手機（iPhone、Android）的加到主畫面與飛航模式。這要 James 的手機，清單在 §6。

## 5. 已知取捨

1. **沒開過的畫面，離線時圖可能不齊。** 只存「載過的檔」。例如圖鑑的大圖是滑到才載的，沒滑過、又剛好離線，那張會是空的或退回符號。有網路時開過一次就有了。沒有選擇「第一次就把 200 多個檔全抓下來」，因為會吃玩家流量。
2. **iPhone 主畫面版的存檔跟 Safari 是分開的。** 這是 iOS 的規定。已經在 Safari 玩到一半的人，加到主畫面後會從頭開始，要用設定頁的**存檔碼**搬過去。合進正式站時，更新公告要講這件事。
3. **忘了加 `?v=` 時，玩家是「下一次開」才拿到新檔，不是當次。** 所以 `?v=` 的紀律照舊，這只是保險。
4. **圖示在圓形裁切的 Android 桌面上，四個角會被切掉。** 現在的圖示是滿版的羊圈畫面，大羊的鼻尖靠邊。要不要另外做一張留邊的，請 James 真機看了再說。
5. **統計沒有分「從主畫面開」與「從瀏覽器開」。** 要知道多少人裝，得在 GA 多送一個欄位。樣品先不加。
6. **說明檔叫 `manifest.json`，不叫常見的 `manifest.webmanifest`。** 測試站（githack）會把後者轉到別的網域，起始網址會失效，跟正式站行為不一樣。改叫 `.json` 兩邊就一致。
7. **測試站的圖是轉址來的**（githack 把圖轉到 GitHub 的原始檔網域）。這種圖第一次載入時存不了，程式會在背景另外抓一份存。所以測試站請**開一次、進一夜玩一下、再重新整理一次**之後再試離線。正式站沒有轉址，沒這個差別。

## 6. 請 James 真機驗收

測試站：<https://raw.githack.com/st00777/sheepfold-defense/feat/pwa-sample/index.html?all>

**iPhone（Safari）**
1. 開測試站，等首頁出來，重新整理一次。
2. 分享鈕，選「加入主畫面」。看桌面圖示與名字對不對。

**Android（Chrome）**
1. 開測試站，重新整理一次。選單裡選「安裝應用程式」或「加到主畫面」。
2. 看桌面圖示：圓形裁切後好不好看（取捨 4）。

## 7. 如果要合進正式站

1. 合併分支，遊戲內版本加一版，更新公告寫「可以加到主畫面、沒網路也能玩」，並提醒 iPhone 存檔要用存檔碼搬。
2. 合併後第一週，每次上版後用一支沒清過的手機點開確認拿到新版。
3. 萬一出事的退路：把 `sw.js` 換成一支「把自己拆掉、清掉存的檔」的版本推上去，玩家下次開就回到沒有這支程式的狀態。這支退路程式到時候我先寫好放著。
