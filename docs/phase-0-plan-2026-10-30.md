# 期 0 地基 施工計畫（2026-10-30）

對應 docs/endgame-blueprint-2026-10-28.md §6 期 0。James 10/29 晚交代：不逐步確認，能做的一口氣做完；GA4 先用靈修冒險那個資源。

## Goal
存檔變成一份有版本號的結構，壞了會說、不會默默清；能匯出成一串存檔碼換手機接著玩；版本更新彈一次三行摘要；匿名統計開始記「玩到哪、用了哪些卡」。背景暫停／減少動態／中斷恢復三項用程式碼巡一遍，列真機清單給 James。

## Constraints
- engine.js、data.js、render.js 不動（這期沒有玩法改動）。
- 新檔 `save.js`：純邏輯、無 DOM，node 測試跑得動（跟 engine.js 同一套做法）。
- 舊玩家的進度一律搬進新結構，搬成功才刪舊 key；搬不動就留著並說明。
- 統計不記姓名帳號，不開 Firebase；設定頁一個開關就能關。開著 `?dev` 的頁面與開過開發者面板的那局不送。
- 改 js 加 `?v=`。

## 我自己定的判斷題（不再問）
- 存檔單一 key `sheepfold-save`（v4）。另有 `-bak`（每次開頁抄一份上次好的）與 `-broken`（主檔讀不出來時留原文）。`sheepfold-lasterr` 是除錯紀錄，不算存檔、不搬。
- 存檔碼格式 `SF4.<base64url(JSON)>.<FNV-1a 8 碼>`：純 ASCII，LINE／備忘錄貼來貼去不會被改字；最後 8 碼是校驗，少字、改字會被擋。
- 匯入一律整份覆蓋（不合併），覆蓋前先顯示那份存檔守過幾夜、幾份檢查點、最後更新日期，再按一次確定；寫入後重新載入頁面。
- 設定頁放首頁左上 ⚙️（右上已是喇叭）。暫停選單維持原樣（大字／省效能／音效）。
- 更新公告只給「已經有存檔」的玩家看；全新玩家直接標成看過。
- GA4 事件四種：`night_start`、`night_end`、`card_used`（每夜每張一筆，帶次數）、`open_codex`。每個事件帶 `game: sheepfold`，共用資源時靠這個分開看。使用者屬性 `player_kind`：第一次接統計時有通關紀錄＝`returning`，沒有＝`new`。
- 續玩那一局的 `card_used` 只算續玩後放的（檢查點不存放卡次數），報表看趨勢夠用。

## Steps
1. `save.js`：empty／fromLegacy／migrate 鏈／validate／open（主檔→備份→舊 key→全新）／save 寫完讀回／encode／decode／summary。
2. `sim/save.test.js`：舊 key 搬移、壞主檔用備份、未來版本拒收、存檔碼來回（含中文）、校驗碼錯誤、檢查點壞掉只丟那一份、`node --test` 全綠。
3. `index.html`：所有 localStorage 讀寫改走 `SAVE`；`sound.js` 改成由外面接存檔（v8）；設定頁（匯出／匯入／統計開關／版本）；更新公告層；首頁存檔狀態一行；GA4 載入與四個事件；`pagehide` 也暫停。
4. 背景暫停／減少動態／中斷恢復：對照程式碼列出已涵蓋與缺口，缺口能補就補。
5. README 存檔段落＋設定段落＋統計說明；藍圖 §3 現況欄更新。
6. 內建 code-review；本機 Chrome 開一局確認無錯；推 `feat/phase-0`，給 githack 預覽與真機清單。
