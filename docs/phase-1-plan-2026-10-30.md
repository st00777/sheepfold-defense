# 期 1 修飾詞介面 施工計畫（2026-10-30）

對應 docs/endgame-blueprint-2026-10-28.md §6 期 1。James 10/30 一句「開期 1」，照期 0 的規矩不逐步確認、一口氣做完。

## Goal
engine 建局時可以套一層「修飾詞」：這一局用哪幾張卡、開局多少糧、幾位看門的、打幾波、要不要送卡模式、要不要一筆糧。期 2 的試煉冊每一題就是「某一夜＋一組修飾詞」，模擬器要能用同一組修飾詞跑勝率，試煉作者寫題前先驗過。

## Constraints
- data.js、render.js、save.js 不動；index.html 只動 `engine.js?v=`（這期沒有玩家看得到的改動）。
- 不給修飾詞時 engine 行為與快照長相一模一樣（舊檢查點照接、舊測試一條不改）。
- 修飾詞是純資料（JSON 放得下），續玩時必須用同一組建局，不同組的檢查點不能接。
- 壞的修飾詞不讓建局失敗：印錯誤、略過那一欄、其餘照套；要事先驗有 `checkMods`。

## 我自己定的判斷題（不再問）
- 六個欄位就好，藍圖列的五項加上「送卡」與「一筆糧」分開兩個開關：`units`、`startFood`、`gates`、`waves`、`conveyor`、`oneBudget`。`maxUnits`、`prep`、`rest`、`moonless`、`hill` 這些不開放——試煉冊首批 6 題用不到，開了就要多驗一倍。
- `units` 是絕對白名單，不限這一夜原本開的卡（試煉可以在第 3 夜的地圖給拋石手）。只有「只能放坡上」的石堆在沒坡的夜會被丟掉。`fresh`／`must` 跟著濾。不檢查張數下限——排陣解謎本來就可能只給兩張。
- `startFood` 寫多少就多少，不乘一筆糧的 `budgetMul`。試煉固定難度，作者要的是確定的數字。
- `gates` 數字照表挑排：1→第 3 排、2→第 2、4 排、3→中間三排、4→第 1、2、4、5 排、5→全部；要特定排就給陣列。0 等於關卡的 `gates: false`，星級跟著只剩兩顆。
- `waves: N` 只打前 N 波，不支援挑第幾波。
- `conveyor: true` 把一般夜變送卡夜：牧人拿掉（沒有糧他沒事做）、7 秒一張、手上最多 6 張、開局隨機 3 張、權重均等；給物件可以自己定 `every`／`max`／`start`／`weights`。`conveyor: false` 把第 11 夜變回有糧的夜（卡要自己用 `units` 補牧人）。
- `oneBudget: true` ＝糧不滴＋沒有牧人；沒給 `startFood` 只提醒不擋（150 糧打一夜大概會輸，但那是作者的事）。送卡模式贏過一筆糧，兩個都開時 `oneBudget` 與 `startFood` 沒作用、會提醒。
- 快照存的是整理後的修飾詞（鍵順序固定），`restore` 用 JSON 字串相等判斷是不是同一組；沒修飾詞的局快照不多這一欄。

## Steps
1. engine.js：`normalizeMods`（驗值、整理成固定形狀、分 problems 與 notes）、`applyMods`（套到關卡副本）、`checkMods`；`create` 第四個參數；`gateRows` 吃陣列；快照／`checkSnapshot`／`restore` 帶修飾詞。
2. 送卡模式兩處補白名單：開局 `start` 的卡、每波 `give` 點名的卡，白名單沒有就不發（發了也放不下去、會卡在手上）。
3. sim/simulate.js：`SIM_MODS` JSON 環境變數；`play`／`run`／`compare` 多一個 `mods` 參數；輸出行印出修飾詞。
4. sim/mods.test.js 9 項；全部測試全綠。
5. README 模擬器一行、藍圖 §6、本檔；內建 code-review；推 `feat/phase-1`。

## Acceptance
- `E.create(3,'calm',rng,{units:['shepherd','slinger','lobber'],startFood:300,gates:2,waves:2})`：只能放這三張（拋石手在第 3 夜放得下）、糧 300、看門的在第 2、4 排、第 2 波清完就天亮。
- `{conveyor:true}` 套在第 5 夜：糧 0、開局三張、沒有牧人；`{conveyor:false,units:[…含牧人]}` 套在第 11 夜：有糧、會滴、手牌空。
- `{oneBudget:true,startFood:500}` 套在第 3 夜：糧不滴、沒有牧人；`{oneBudget:false}` 套在第 25 夜：糧又會滴。
- 有修飾詞的檢查點只能接同一組（寫法不同、順序不同算同一組）；沒修飾詞的局接不了、被改壞的欄位不收。
- `SIM_MODS='{…}' node sim/simulate.js 3 calm 30` 跑得動、輸出行看得到修飾詞；壞 JSON 直接停。
- 不給修飾詞：130 項測試裡原本的 121 項一條沒改全綠。

### 內建 code-review（high）10 條的處置
修了八條：①`conveyor.start: 0` 被 `st || 3` 當成 3 張→改 `??`；順便發現手牌空著永遠開不了局（放下第一張才開始送卡），所以開局手上沒卡就補抽一張；②第 11 夜自己的權重表跟白名單沒交集→一張都抽不到，改成權重表只留白名單上的、沒交集就均等抽，`checkMods` 會提醒；③白名單只剩牧人又開送卡／一筆糧→拿掉牧人變空名單，改成 problem 並略過 `units`；④卡名驗證用 `UNITS[k]` 真假會放過 `constructor`／`toString` 這種原型鏈名字→改 `hasOwnProperty`；⑤`oneBudget: false` 只關旗標、第 25 夜的 1600 糧還在→沒另給 `startFood` 就一起回預設，並提醒要用 `units` 補牧人；⑥`conveyor.weights` 鍵順序不同被當成另一組→整理時照字母排；⑦模擬器 `SIM_MODS` 不合某夜時每局印一行洗版→每個「夜＋難度」只印一次、建局時壓掉引擎的訊息；⑧`compare` 多一個佔位的 `_skill` 參數是陷阱→拿掉，CLI 分開呼叫。順手：提醒（notes）改 `console.warn`，錯誤才 `console.error`；`applyMods` 三處重複的卡表過濾抽成 `restrict`；有修飾詞的局續玩時白名單外的卡不還原（故事模式照舊，玩家換過隊伍的舊檢查點不能丟）；模擬器 `decideConveyor` 手牌空時會炸，補了 guard。測試 130→131（一條合併加長）。

### 給期 2 的交接
- 一題試煉＝`{ levelId, diff, mods, 題目文字 }`；寫題時先 `Engine.checkMods(levelId, mods)` 看回傳是不是空陣列，再 `SIM_MODS` 跑 50 局看勝率，再找一位真人。
- 試煉局的檢查點要另存（不能跟故事模式的 `checkpoint[levelId]` 混），存檔結構要加一欄，走 save.js 的 STEPS 升版。
- 試煉頁要把修飾詞翻成人話：白名單→顯示那幾張卡、`gates`→「看門的 N 位」、`waves`→「只有 N 波」、`conveyor`→「拉班送卡」、`oneBudget`→「就這些糧」。
- 送卡模式的開局卡與點名卡現在都看白名單；若要「這波一定送 X」，X 要在 `units` 裡。
